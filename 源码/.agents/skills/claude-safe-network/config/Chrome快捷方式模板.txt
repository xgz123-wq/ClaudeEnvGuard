Windows Chrome 快捷方式「目标」示例（单行复制）：

"C:\Program Files\Google\Chrome\Application\chrome.exe" --user-data-dir="%LOCALAPPDATA%\ClaudeAccountBrowsers\<别名>\UserData" --proxy-server="socks5://127.0.0.1:43866" --host-resolver-rules="MAP * ~NOTFOUND, EXCLUDE 127.0.0.1, EXCLUDE localhost" --lang=en-US --accept-lang="en-US,en" --force-webrtc-ip-handling-policy=disable_non_proxied_udp --disable-quic

操作：
1. 核对 Chrome 安装路径；如实际在其他目录，只替换前面的 chrome.exe 路径。
2. 新建快捷方式，将上面完整一行填入「目标」；命名为 `Claude-<别名>-专用Chrome`。别名由你自己定，不要沿用示例值。
3. 该 User Data 是独立浏览器数据目录。首次使用应为空，不复制旧 Profile 或 Cookie。
4. 每个账号使用不同目录（`ClaudeAccountBrowsers\<另一个别名>\UserData`）。操作前完全退出该目录对应的旧 Chrome 进程。
5. 从新快捷方式打开 Chrome，在地址栏输入 chrome://version。
6. 检查「命令行」含 43866、--user-data-dir；检查「个人资料路径」位于独立目录下。
7. 再打开 https://ip.net.coffee/claude/，检测出口、DNS、WebRTC 和 IPv6；没有观察到真实请求前，不算验收完成。

边界：
- 43866 必须与全局脚本的 socksPort 一致；SOCKS 入站只在 127.0.0.1 监听。
- IN-NAME 会将此浏览器通过该入站的流量送入 ACCOUNT-US，包含它访问的国内 API。
- WebRTC / QUIC 参数是降低特定 UDP 路径风险的设置，不能据此宣称整个系统永久防泄漏。
- Chrome 版本更新可能改变参数行为；参数存在不等于检测已通过。
- `--host-resolver-rules` 让 DNS 也走代理，是本套件的固定参数；Chrome 可能提示"不支持的命令行参数"，那是 Chromium 对未知参数的通用提示，**不要因此删掉它**。
- 桌面快捷方式的实际参数以 `config\Topology.psd1` 的 `ChromeArgs` 为准，本模板只是手工对照用。
- chrome:// 内部页面通常不能从普通 HTML 链接直接打开，请复制地址到浏览器地址栏。
