# 05 · 闭环清单（九层）

> 「一套配好、长期可复用」到底包含哪些东西？这张表就是答案。
> 各层是**依赖顺序**：上面一层断了，下面所有层都会悄悄失效（尤其 Desktop 那层）。
> 每层的实测基线是 2026-09-13 的快照；基线变了要更新 `00-baseline.md`。

> 「项数」按编排器输出的行数算（PASS + WARN + FAIL + MANUAL）。**`MANUAL` 现在是 0。**
> 全量行数 116～120（差异全在 L7，见下方 ping0 说明）。

**一键跑全部**：

```powershell
pwsh -File scripts\Invoke-ClaudeSafetyCheck.ps1              # 9 层全跑（约 1 分钟，耗时随检测站响应波动）
pwsh -File scripts\Invoke-ClaudeSafetyCheck.ps1 -Fast        # 跳过联网层（约 10～16s）
pwsh -File scripts\Invoke-ClaudeSafetyCheck.ps1 -Only proxy,desktop
pwsh -File scripts\Invoke-ClaudeSafetyCheck.ps1 -Fast -Json  # 机器可读
```

**判定**：现行判定以脚本实时输出为准：`0 FAIL`、退出码 `0` 即通过，`WARN` 逐条确认。
历史参考（2026-09-13 实测，后来检查项有增加，不作为现行验收线）：全量 `114 PASS / 2 WARN / 0 FAIL / 0 MANUAL`，`-Fast` `61 / 0 / 0 / 0`。
`ping0.cc` 未被限流时为全量 `119 PASS / 1 WARN / 0 FAIL / 0 MANUAL`。

**计数里没有任何 `MANUAL`。** 唯一需要「一次 UAC」的步骤是 WFP 实盘核对，它已降级为「一条命令 + 缓存 30 天」：

```powershell
pwsh -File scripts\checks\Request-ElevatedVerify.ps1 -Refresh   # 弹一次 UAC，点「是」（实测 9 秒完成）
pwsh -File scripts\checks\Request-ElevatedVerify.ps1 -Status    # 之后随时查还有效多久
```

> **若 ping0.cc 恰好被网站风控挑战页拦下**（短时间内反复自动访问同一出口时会触发，属**站点按出口 IP 限流**，不是本机配置问题）：
> L7 从 12 行降为 8 行，多出一条 WARN。等一会儿再跑即恢复；急的话 `-OpenBrowser` 用浏览器人眼复核。
> ⚠️ 排查期间**不要连续手跑 ping0 探测**，那只会延长限流。

## L1 · Clash 全局配置（整套配置的真正主体）

配置实体**不在订阅里**，而在这一个文件：

```
%APPDATA%\io.github.clash-verge-rev.clash-verge-rev\profiles\Script.js
```

它是 Clash Verge Rev 的**全局扩展脚本（global extend script）**，与订阅无关、换订阅不失效。
skill 内的权威副本是 `scripts\clash\Clash全局账号通道.js`，`Check-PortConsistency.ps1` 会核对两者 SHA256。

| 它做的 6 件事 | 为什么必须这么做 |
|---|---|
| ① 重建 `ACCOUNT-US` 组（`include-all-proxies: true`） | 换任何订阅，节点自动进组，**规则一行都不用改** |
| ② 对 12 个 Claude 域名写 `dns.nameserver-policy`（走 `#ACCOUNT-US`） | 防止 DNS 在本地被解析→域名前置绕过代理 |
| ③ 强制 `tun.strict-route=true` + `dns-hijack=["any:53","tcp://any:53"]` | 堵 TUN 旁路与 53 端口泄漏 |
| ④ 注入 2 个 listener：`account-us-socks`(43866 SOCKS5)、`claude-desktop-http`(43867 HTTP) | Claude 三入口物理分开：Code 用 43865、Chrome 用 43866、Desktop 用 43867 |
| ⑤ 把 Claude 规则**幂等置顶**（专用域名 + IP-CIDR + IP-CIDR6 + IP-ASN 399358） | 订阅自带规则再多也压不住它；重复运行不会堆叠 |
| ⑥ `geox-url.asn` 兜底 | GeoLite2-ASN 缺失时仍能按 ASN 分流 |

**显式不做**：**不覆盖** `nameserver` / `direct-nameserver` / `fallback`。
（2026-09-10 曾因覆盖 DNS 导致飞书断网，这条是事故换来的。）

### L2 · 代理入口与运行时

| 检查项 | 合格线 |
|---|---|
| 三个端口监听且同属一个 `verge-mihomo` 进程 | 43865/43866/43867 都在 `127.0.0.1`，PID 相同 |
| `verge.yaml` `enable_tun_mode` | `true`（日常模式）；用 Claude Desktop 前也保持 `true` |
| `verge.yaml` `enable_system_proxy` | **`false`** —— 系统代理永远关 |
| `mode` | `rule`，**绝不能是 `global`**（全局模式会烧流量，用户的原始约束） |
| `mixed-port` | 与 `config\Topology.psd1` 的 `Ports.Mixed` 一致 |
| `strict-route` / `auto-route` / `dns-hijack` | 全为开 |
| 三入口出口 IP | 完全一致 |

> **为什么不用全局模式**：流量成本。规则模式 + 全局脚本注入的置顶 Claude 规则，
> 已经把 Claude 全链路兜住了，不需要全局。

## L3 · Claude Code

配置实体：`~\.claude\settings.json`（另有 `~\.claude\mcp.json`）

| 检查项 | 合格线 | 说明 |
|---|---|---|
| `env.ALL_PROXY / HTTPS_PROXY / HTTP_PROXY` | `http://127.0.0.1:43865` | 这就是「进程级代理」——**等价于外部装 Proxifier，所以不用装** |
| `env.NO_PROXY` | 含 `localhost,127.0.0.1,*.local` | 防本机回环被代理绕一圈 |
| 协议 | **必须是 http，不能是 socks5** | Claude Code 官方只支持 HTTP/HTTPS 代理 |
| 系统环境变量 | **不得**存在 `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`/`ANTHROPIC_BASE_URL` | 系统级代理会被扫、且影响所有软件 |
| `ANTHROPIC_BASE_URL` | **不得设置** | 指向中转 = 明文经过第三方，红线 |
| `.credentials.json` | 只报存在性 | **脚本从不读取内容** |

> `DISABLE_AUTOUPDATER`、`model`、`effortLevel` 等属于个人偏好，检查脚本只记录不改。

## L4 · 专用 Chrome（账号隔离）

| 检查项 | 合格线 |
|---|---|
| 每个账号独立 User Data 目录 | `%LOCALAPPDATA%\ClaudeAccountBrowsers\<账号>\UserData`，账号之间不共享 |
| `--proxy-server` | `socks5://127.0.0.1:43866`（Chrome 可以走 SOCKS，Code 不行） |
| `--host-resolver-rules` | `MAP * ~NOTFOUND, EXCLUDE 127.0.0.1, EXCLUDE localhost` —— **DNS 也走代理** |
| `--lang` / `--accept-lang` | `en-US` —— 与出口地区对齐，减少"IP 美国 + 语言中文"的错位信号 |
| `--force-webrtc-ip-handling-policy` | `disable_non_proxied_udp` —— 防 WebRTC 泄漏真实 IP |
| 快捷方式 | 由 `scripts\apply\Repair-Shortcuts.ps1` 从 `assets\shortcuts\` 备份**还原**（只还原、不重建），指向 `docs\配置\` 原路径 |

`Topology.psd1` 的 `Accounts` 定义账号列表（示例 3 节，安装时按需增删）。新增账号：在 `Accounts` 里加一节，
再用 `scripts\apply\创建账号浏览器.ps1 -Alias <别名>` 生成独立浏览器目录与快捷方式，最后用
`Repair-Shortcuts.ps1` 校验快捷方式。

## L5 · Claude Desktop（最容易翻车的一层）

| 检查项 | 合格线 | 翻车方式 |
|---|---|---|
| `HKLM\SOFTWARE\Policies\Claude` 的 `egressProxyUrl` | `http://127.0.0.1:43867` | 路径写错（**没有** `Anthropic` 中间层，历史上猜错过） |

## L6 · Windows 系统兜底

| 检查项 | 合格线 | 说明 |
|---|---|---|
| **WFP 精确阻断 8 条** | 4 个 `claude.exe` × IPv4/IPv6 各 1 条，全部 `Enabled` + 精确 AppID + 非回环 | Desktop、两个 CLI 路径和 VS Code 插件；不阻断 `Code.exe` |
| 实盘核对 | 需**管理员**（内核过滤器只有管理员能读） | 已内置**一次 UAC + 30 天缓存**：`pwsh -File scripts\checks\Request-ElevatedVerify.ps1 -Refresh`，之后自动读缓存判 PASS/FAIL，不再报人工项 |

### 网页层（无头 Chrome 真实渲染，自动）

| 站点 | 看什么 | 合格线 |
|---|---|---|
| `ip.net.coffee/claude/` | Claude 专向六项：出口 IP / Trust Score / IP 属性 / 风险信号 / 滥用记录 / 支持地区 | 出口 IP 与其它入口一致；Trust ≥ 80；家庭住宅IP；风险信号全「未检测到」；无滥用记录 |

> `ippure.com` 是唯一仍需人眼的站点：它的取数要求一枚由混淆 JS 现场算出的 `x-t` 签名头，
> 属于**算法门槛**而不是**渲染门槛**，自动化不划算。脚本会在末尾打印交接清单与跳转命令。
> 其余两站的实测取数配方（含「哪些字段必须从纯文本取、哪些必须从 DOM 取」）见 `04-Ip信誉检测.md`。

## 贯穿 · 端口一致性

端口真源只有一处：`config\Topology.psd1` 的 `Ports`。

| 检查项 | 结果 |
|---|---|
| 真源 vs `verge.yaml` `verge_mixed_port` | 一致 |
| 真源 vs 运行时 `mixed-port` | 一致 |
| 真源 vs 实际监听 | 三个端口都在监听 |
| 真源 vs `Script.js` 内两个 listener | 一致，且与 skill 权威副本哈希相同 |
| 真源 vs 桌面快捷方式参数 | 取值正确 |
| **漂移检测** | 扫同族端口号（`438xx` / `789x` / `909x` / `1080x`），凡不在真源里的报 WARN |

**已知取舍（如实说明）**：另有若干旧文件含端口**字面量**（文件和行数以检查脚本实时输出为准）。
这些是历史脚本里的硬编码，没有全部改成读 `Topology.psd1`，因为：

1. 改散落在多个旧文件里的硬编码，风险远大于收益（很多是一次性已执行完的安装/回滚脚本）；
2. 真正需要跟端口走的部分（主入口、编排器、9 个 checks）**已经**从 `Topology.psd1` 取；
3. 剩下的用**漂移检测**覆盖——改端口时跑一次 `Check-PortConsistency.ps1`，它会输出「文件:行号」清单，照单同步即可。

所以这一层不是"全自动"，而是"真源 + 清单 + 告警"。详见 SOP-3。
