# 验收与排查手册

## 1. 验收体系

| 层 | 工具 | 什么时候用 | 结果如何判读 |
|---|---|---|---|
| **程序层（全量）** | `Invoke-ClaudeSafetyCheck.ps1`（9 层编排器） | 变更后 / 定期 / 想一次看全 | `FAIL = 0`（exit 0）；`WARN` 逐条确认 |
| **程序层（自动化）** | `Claude环境一键总检.ps1` | 例行 / 变更后 / 启动 Claude 前 | 有 `FAIL` → **不建议启动 Claude**（exit 1）；只有 `WARN` → 提示「不能当成已验收」 |
| **程序层（垂类）** | `Claude日常五项自检.ps1`（5 项） | 每天顺手跑 | 每项 PASS |
| **底层引擎** | `验证Clash账号专用通道.ps1`（输出 JSON） | 被上面两个调用；也可单独跑 | `Success=true` |
| **Desktop 门禁** | `启动Claude英文浏览器.ps1`（`-CheckOnly` 只检查） | 每次开 Desktop 前 | `[PASS]` 才启动，否则 `[BLOCK]` |
| **外部信誉** | 四大 IP 站 + `Check-IpReputation.ps1` | 换订阅 / 换节点 / 每月 | 见下方判读标准 |
| **网页层（自动 3/4）** | `ping0.cc` / `iprisk.top` / `ip.net.coffee` 由无头 Chrome 渲染自动判定；`ippure.com` 仍建议人眼（`-OpenBrowser` 打开） | 程序层全绿后 | 见 §2 判读标准 |

常用开关：`-Fast`（跳过联网层 1/3/7/8）、`-Only proxy,desktop`（只跑指定层）、`-Json`（输出带 `===JSON-BEGIN===` 标记的机器可读块）、`-OpenBrowser`（把网页复核开进专用 Chrome）。

**判定**：现行判定以脚本实时输出为准：`0 FAIL`、退出码 `0` 即通过，`WARN` 逐条确认。`-Fast` 不弹 UAC。
历史参考（2026-09-13 实测，后来检查项有增加，不作为现行验收线）：全量 `114 PASS / 2 WARN / 0 FAIL / 0 MANUAL`，`-Fast` `61 / 0 / 0 / 0`。

**计数里 0 个 `MANUAL`**（原有 5 项已全部自动化）。2 条 `WARN` 都良性：
① iprisk「IP 使用时间较短」（新 IP 必然扣，非缺陷）；② `ping0.cc` 被 Cloudflare Turnstile 挑战页拦下（站点按出口 IP 临时限流，与本机配置无关）。

唯一需要「一次 UAC」的步骤是 WFP 实盘核对，它不是"要你手填"，而是**一条命令 + 点一次「是」**：

```powershell
pwsh -File scripts\checks\Request-ElevatedVerify.ps1 -Refresh
```

跑完写入 `config\elevated-verify-cache.json`；缓存必须同时绑定清单 SHA256、Desktop 版本和全部规则 GUID，当前合格值是**实盘 8/8 在位**、`DesktopVerifyStatus=passed`。
**30 天内全量总检直接判 PASS，不再提示**。到期或 Desktop 升级（`PackageVersionMatches=false`）会降级为 `WARN`（**不静默放行**）。
平时想确认是否还在有效期内：`… -Status`（exit 0 = 新鲜有效，4 = 还没做过）。

### 一键总检的检查项

1. 基础验证程序（内联，全部通过） 2. `Rule/TUN/Claude 规则` 3. 国内连通（飞书 HTTP）
4. `ACCOUNT-US` 当前节点 + 43866 出口 IP 5. DNS 防旁路（strict-route + 53 劫持）
6. Code 43865 出口 7. Chrome 43866 出口 8. Desktop 43867 出口 9. **三入口一致性**
10–11. 两个专用 Chrome `.lnk` 参数齐全 12. **Desktop 本地代理**（HKLM 优先，退化到 configLibrary）
13. Desktop 自动更新被禁（且同层保留 43867） 14. **Desktop 直连阻断**（校验清单哈希 + 状态/Verify/Install 记录）
15. **检测站自动读数**（`Get-WebAcceptanceVerdict` 自动读 ping0 + ip.net.coffee 后判 `PASS`/`WARN`）；**网页最终验收**仍为 `MANUAL`，由用户在专用 Chrome / Desktop 里人眼确认

> 第 1 项「基础验证程序」是内联程序验证，打印在正文里、**不计入结果行**。所以脚本自己打印的「结果行」比上面列出的条目少 1 项，以脚本实际输出为准。

### 日常五项自检的五项

1. 干净住宅 / ISP IP（看网页）
2. 禁用 IPv6（`clash-verge.yaml` 的 `ipv6:false` **且**实体网卡 IPv6 关闭）
3. DNS 走代理（`ClaudeDnsUsesAccountUS` & `NoDnsBoundToOtherGroups` & 浏览器入口参数）
4. 固定出口不乱切（`AccountNodeSelected` & `SocksHasPublicIpv4`）
5. Claude 单独分流且优先（`AccountRuleExactlyOnce` & `ClaudeRulesUseAccountUS` & 浏览器参数）

## 2. 三大 IP 信誉站的判读标准

| 站点 | 看什么 | 合格线 |
|---|---|---|
| `ping0.cc` | 风控值、IP 类型、是否原生 | 风控值 **< 20%**；类型 = 家庭宽带 / ISP；**原生 IP** |
| `ippure.com` | 人机占比、IP 来源属性 | 系数 **0%**；住宅 IP；原生 IP；human 明显高于 bot |
| `iprisk.top` | Scamalytics 欺诈分、IPQuality、黑名单 | 纯净度 **≥ 90/100**；机房票 **0**；黑名单**全清** |

**判读红线**：三站只要出现「机房 / 数据中心」标签或黑名单命中 → **换节点**，别硬扛。
**唯一可接受扣分**：`新 IP < 3 月` 这类时间分（新租的 IP 必然扣，等自然变老即可）。

**注意**：这三个站是**第三方信誉参考**，不等于 Anthropic 官方认证。文档明确
`ip.net.coffee/claude/` **不是配置层**，只是运行态人工验收工具。

## 3. 故障决策树

按顺序查，**每一步都有明确命令和期望值**：

### 第 -1 步：是不是宽带链路限包（MTU 黑洞）

**症状**：国内网站正常、走代理的网页全打不开、托盘提示「Mihomo 无法访问 Internet」。先做这一步再查节点，30 秒定性。

```powershell
ping -f -l 1472 8.8.8.8    # 超时 = 链路过不了 1500 字节的包
ping -f -l 1464 8.8.8.8    # 通 = 链路上限约 1492（PPPoE 特征值）
```

| 结果 | 结论 | 处理 |
|---|---|---|
| 1472 通 | 不是 MTU 问题 | 进第 0 步 |
| 1472 超时、1464 通 | 链路变小，路由器/光猫丢大包且不回报错 | 核对下面两处设置 |
| 1472 报「需要拆分」 | 本机 MTU 已小于 1500，是修复后的正常现象 | 进第 0 步 |

| 位置 | 应设值 | 查法 / 改法 |
|---|---|---|
| Clash → 设置 → 虚拟网卡模式 → 最大传输单元 | `1380` | 用户在界面改；现场值见 `clash-verge.yaml` 的 `tun.mtu` |
| Windows 上网网卡（当前 `WLAN`） | `1400` | `netsh interface ipv4 show subinterfaces`；管理员 `netsh interface ipv4 set subinterface "WLAN" mtu=1400 store=persistent` |

- **两处都要设**：mihomo 连节点的包从物理网卡发出，只改 TUN 不保证恢复。
- **换网卡要重设**：插网线或换无线网卡后，新网卡默认 1500。
- **易被重置**：Clash 升级或重置、Windows 网络重置、重装网卡驱动后复查。
- **根治在路由器**：WAN 口 MTU 设 1492 并开 MSS 钳制，家里其他设备也一并修好；路由器和光猫由用户处理。
- **误判陷阱**：节点测速用 `generate_204`（无响应体），在 MTU 黑洞下会假通过；验证要用有响应体的目标。2026-10-05 一次排查因先查订阅和节点，绕了很久。

### 第 0 步：是不是根本没起来

```powershell
# 三端口是否都在监听、是否都属于 verge-mihomo
Get-NetTCPConnection -State Listen |
  Where-Object { $_.LocalPort -in 43865,43866,43867 } |
  ForEach-Object { "port={0} pid={1} proc={2}" -f $_.LocalPort, $_.OwningProcess,
    (Get-Process -Id $_.OwningProcess).ProcessName }
```
期望：三个端口各 1 行，`proc=verge-mihomo`。缺哪个 → 看 `Script.js` 是否被 Verge 正确加载（Verge 界面「订阅 → 全局扩展脚本」是否能预览）。

### 第 1 步：组选没选中

```powershell
# 走命名管道 API（9097 未监听，别用 HTTP）
# 需要按 chunked 读法解析；简化：直接看 Verge 界面「代理」页
```
期望：`ACCOUNT-US` 有**已选中**节点（不是空、不是「-」）。空 → 说明**新订阅的节点没自动选中**，手动选一个。

### 第 2 步：规则在不在、指向对不对

期望（运行时）：
- 规则总数 ≈ 47（会随订阅变，但**第 1 条永远** `InName account-us-socks -> ACCOUNT-US`）
- Claude 域名规则全部指向 `ACCOUNT-US`
- 没有指向订阅自带组名的规则或 DNS 绑定后缀

### 第 3 步：出口一致性

```powershell
# 四个入口必须同一个 IP
curl.exe --max-time 10 -s https://api.ipify.org                                   # TUN 直连
curl.exe --max-time 10 -s --proxy http://127.0.0.1:43865 https://api.ipify.org     # Code
curl.exe --max-time 10 -s --proxy socks5h://127.0.0.1:43866 https://api.ipify.org  # Chrome
curl.exe --max-time 10 -s --proxy http://127.0.0.1:43867 https://api.ipify.org     # Desktop
```
四个不相同 → **不要用 Claude**，先查规则/组。

### 第 4 步：DNS 有没有旁路

- `clash-verge.yaml` 里 `strict-route: true`、`dns-hijack: [any:53, tcp://any:53]`
- 探针 DNS 应返回 Clash fake-IP 段 `198.18.0.0/16`（基线实测 `198.18.0.53`）
- 探针 `absentProxy` 应 `ECONNREFUSED`（43867 不在时**无回退** = 好事）
- **浏览器自带加密 DNS（DoH，走 443）不受 53 劫持**：会按普通流量落兜底规则 → 进美国线路 → 国内域名被解析成海外 IP、直连海外 IP 卡慢（2026-09-28 Edge 实例）。排查：连接表搜 `cloudflare-dns.com` 等端点，`netstat -ano -p udp` 按源端口反查进程；修复：浏览器「安全 DNS」关闭或指向国内 DoH，改完彻底重启浏览器。现场 `Script.js` 已把 `cloudflare-dns.com` / `dns.google` 置为直连兜底

### 第 5 步：Desktop 专项

1. `HKLM\SOFTWARE\Policies\Claude` 的 `egressProxyUrl` **与** `disableAutoUpdates` **必须同层存在**
2. `configLibrary\_meta.json` 的 `appliedId` 指向的文件内容是 `{"egressProxyUrl":"http://127.0.0.1:43867"}`
3. `维护文件\应用直连防护状态.json` 里的 8 条 filter 与 `应用过滤目标.json` 的哈希对得上
4. 注意：Desktop 启动脚本里的 `Assert-GuardEvidence` 是**门禁**，不通过会 `[BLOCK]`

### 第 6 步：升级后必查

Desktop 每次升级都会换目录 `WindowsApps\Claude_<版本>_x64__pzs8sxrjxfjjc`，VS Code 插件升级也会换版本目录；**WFP 的精确 AppID 条件会失效** → 必须迁移对应规则，并更新 `应用过滤目标.json` 里的路径与 SHA256。

## 4. 环境与编码坑（会真实浪费时间的）

| 坑 | 现象 | 解法 |
|---|---|---|
| **必须 pwsh 7** | 用 `powershell.exe` 5.1 跑本项目脚本 → 报大量 `Unexpected token '}'`、中文变乱码 | 脚本是 **UTF-8 无 BOM**，5.1 按 GBK 读。用 `C:\Program Files\PowerShell\7\pwsh.exe`（桌面 `.lnk` 就是这么配的） |
| **5.1 与 7 共存 ≠ 冲突** | 看到两个 `powershell.exe` / `pwsh.exe` 就以为装重了 | 5.1（`C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`，系统组件）**不可卸载**；7（`C:\Program Files\PowerShell\7\pwsh.exe`）是独立安装。**不要卸载 5.1**。正确做法 = 脚本一律显式用 `pwsh.exe` 全路径调用，并在脚本头写 `#requires -Version 7.0`（本套件 28/28 全覆盖）。第 9 层会扫 `powershell.exe` 残留（注释里的提及不算）。想手工跑脚本也走 7：SOP-3C 可加 `.ps1` 右键「用 PowerShell 7 运行」 |
| **bash 工具 = WSL** | `python` 不存在；`env` 不是 Windows 的 env | 查 Windows 一律走 `pwsh.exe` |
| **bash 吞 `$`** | `$PWD`、`"$f"`、`for` 循环变量全失效；中文参数被吞 | 写 `.ps1` 文件（纯 ASCII 内容）再 `-File` 执行；**不要**在 bash 里拼 PowerShell 单行命令 |
| **中文文件名** | 变量拼中文路径失败；输出标题乱码 | 用 ASCII 通配符 + `Get-ChildItem -Recurse \| Where-Object { $_.Directory.FullName -like '*关键字*' }` 定位 |
| **WSL 删文件** | `rm -f "C:/..."` 静默失败 | 用 `/mnt/c/Users/...` 路径 |
| **`Invoke-WebRequest` 无 `-SkipHttpErrorCheck`** | 5.1 上取不到非 2xx 响应 | 用 `curl.exe` |
| **WSL 访问 `127.0.0.1:43865` 失败** | 跨命名空间 | 必须用 Windows 侧进程（`pwsh.exe`）测 |
| **`netsh wfp show filters` / Verify 需管理员** | `0x00000005` = `ERROR_ACCESS_DENIED` | 提权运行。本套件已封装为「**点一次 UAC + 缓存 30 天**」：`pwsh -File scripts\checks\Request-ElevatedVerify.ps1 -Refresh`，之后第 5 层自动读缓存判 PASS/FAIL（`-Status` 查有效期） |
| **无头 Chrome 三条硬性要求** | 抓 `ping0.cc` 得 41 字节空页；抓 `ip.net.coffee` 只得半成品页（数字还没注入） | ① **真实 UA**（`Get-RealUa` 从本机 `chrome.exe` 现取主版本）；② **独立 `--user-data-dir`**（否则 URL 被转交已有实例后立刻退出）；③ **必须 `--virtual-time-budget=8000`**（只给 `--timeout` 会拿到 5s 时的半成品页）。详见 `04-Ip信誉检测.md` |
| **`Start-Process -RedirectStandardOutput` 读回 0 字节** | 重定向抓 DOM，父进程紧接着读抛 "file is being used by another process"，或读回空 | 改成 `ProcessStartInfo` 直读管道。**且必须先起 `ReadToEndAsync` 再 `WaitForExit`**，否则十几万字节的 DOM 会把管道堵死 |
| **正则 `检测到$` 会误命中「未检测到」** | 风险信号明明全「未检测到」，却被判成「检测到」而报 FAIL | 判定要写成 `($_ -match '检测到') -and ($_ -notmatch '未检测到')`。同类陷阱：裸 `出口IP` 会命中 `Cloudflare 出口IP`（须锚定 `Claude AI出口IP`）；`Trust Score` 在 DOM 上会误匹配成 `6`（须从纯文本取） |
| **Plain 文本 ≠ DOM** | 用 DOM 取「IP 类型」命中的是 `title` 提示里的反例词 `IDC机房IP` | 要「人眼看到的最终值」一律用 `ConvertTo-PlainText` 的输出；只在取 HTML 属性（`usecount=`）或需要 HTML 结构（`riskcurrent` + `<span class="value">`）时才用 DOM。逐字段取舍见 `04-Ip信誉检测.md` 的字段表 |
| **mihomo 命名管道 API** | 9097 未监听；`/proxies`、`/rules` 大响应是 `Transfer-Encoding: chunked` 且**永不 EOF** | 用 `\\.\pipe\verge-mihomo`；边读边探测累积串是否以 `"0\r\n\r\n"` 结尾；`while(Read>0)` / `ReadTimeout` / `BeginRead` 都会**死锁**。小响应是 `Content-Length`，按长度截断，分块体需按 hex 长度手工解码 |
| **检测站按出口 IP 限流** | 短时间内反复自动跑，`ping0.cc` 开始返 1410 字节的 Cloudflare Turnstile 挑战页 | 识别特征已内置（`Test-CaptchaGate`）。这是**站点行为**，不是本机配置问题：等一会儿再跑即恢复；急的话 `-OpenBrowser` 人眼看。脚本此时如实报 **WARN**（不冒充 PASS） |

## 5. 明确的「不是问题」

以下现象看起来像泄漏，**实际是设计预期**，不要误报：

- 探针 `claude-network-probe.exe` 报 `stunUdp4.ok=true` / `directTcp4=connected`
  → 它**不在** WFP 精确规则名单里（只锁 4 个登记过的 `claude.exe`）。
- 探针 DNS 返回 `198.18.0.53`
  → Clash fake-IP 段，**说明 DNS 没旁路**。
- 探针 `absentProxy = ECONNREFUSED`
  → 43867 不在时**无静默回退到直连**，这是期望行为。
- `HKLM\SOFTWARE\WOW6432Node\Policies\Claude` 存在
  → `SOFTWARE\Policies` 不受 WOW64 重定向，这是冗余镜像，无害。
- 静态 `config.yaml` 里 `strict-route: false` 而运行时有 `true`
  → `Script.js` 在运行时覆盖，**以运行时为准**。
- `Verify.json` 是 `failed`
  → 未提权，不是规则缺失。真正判据是 `维护文件\应用直连防护-Verify.json` 的 `Status=passed` 与 `PackageVersionMatches=true`。
- 第 5 层报 `[WARN] Windows WFP 实盘核对：30 天内未提权复核`
  → 规则本身没问题，只是缓存过期/没建。跑一次 `Request-ElevatedVerify.ps1 -Refresh` 点「是」即可转 PASS。
