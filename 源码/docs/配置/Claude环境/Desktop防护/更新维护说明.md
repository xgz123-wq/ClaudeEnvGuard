# Claude Desktop 更新维护说明（给 AI）

> 更新日期：2026-10-06
> 通用流程（识别需求、五步 SOP、收尾记录）见 [claude-maintenance](../../../../.agents/skills/claude-maintenance/SKILL.md)；本页只写 Desktop 专有细则。当前版本与历次证据见 [维护日志](../维护日志.md)。

## 入口

| 文件 | 用途 |
|---|---|
| `更新三端Claude.ps1` | 三端更新编排（默认入口）：`-Action Plan` 一次输出三端版本对比、四个目标指纹和唯一要执行的那条命令（结果里的 `Command` 字段）；`-Action Run` 直接执行，全程只弹一次 UAC。有 claude 进程在跑就报 `blocked_running` |
| `查询Claude最新版本.ps1` | 只查不下：向官网查 Desktop、CLI、VS Code 插件最新版并与本机比较，输出谁落后。不下载、不提权 |
| `下载ClaudeDesktop官方包.ps1` | 自动识别系统与架构，从官方入口查最新版；已是最新只报告，否则下载并调用 Inspect 审核，输出 `PackagePath`、`SHA256`。已按版本名落盘且审核通过的包直接复用，不重复下载。`-CheckOnly` 只查不下。不提权、不安装 |
| `一键更新ClaudeDesktop.ps1` | 统一入口：`-Action Verify` 只核验；`-Action Update -PackagePath '<官方包绝对路径>' -ApprovedSHA256 '<审核后指纹>'` 更新 Desktop；再加 `-CliApprovedSHA256 '<h1>','<h2>','<h3>','<h4>'` 在同一次提权里刷新清单中 4 个目标的指纹；只更新 CLI 同路径文件时只传 `-CliApprovedSHA256`；插件换版本目录时加 `-PluginApprovedSHA256 '<新插件审核后指纹>'`，在同一次提权里最先迁移 |
| `更新ClaudeDesktop.ps1` | 底层：官方包审核、Stage、预保护、Register |
| `应用直连防护管理.ps1` | 管理员 Verify、同路径 Refresh、插件换目录 MigratePlugin、独立阻断探针 |
| `../启动Claude英文浏览器.ps1` | `-CheckOnly` 只检查，不启动 Desktop |

- **授权**：CLI 指纹刷新、Desktop 迁移、管理员 Verify 都在 `一键更新` 的同一个工作进程里，正常只弹一次 UAC。单独以管理员身份运行 `应用直连防护管理.ps1 -Action Refresh` 会多弹一次（09-25 那次共弹 3 次就是这个原因）。
- **清理**：`Update` 全部核验通过后，自动删除 `%ProgramData%\ClaudeNetworkGuard\` 和 `%LOCALAPPDATA%\ClaudeNetworkGuard\Desktop安装包下载\` 里的 `Claude-<版本>.msix`（从 Codex 发起时，还会清理 `Packages\*\LocalCache\Local\ClaudeNetworkGuard\Desktop安装包下载\`），删除清单写进 `结果.json` 的 `Cleanup`；失败时保留安装包，供 `-ResumeJournal` 续接。
- **运行中的 Claude**：发现正在运行时停止维护，不强杀用户任务。

### 状态与组件文件

除 `应用直连防护-Refresh.json` 外都会被脚本读取；文件名和位置写死在脚本里，移走或删除会让总检 FAIL、启动器拒绝启动。

| 文件 | 性质 | 读取方 |
|---|---|---|
| `应用过滤目标.json` | 配置：受保护的 4 个程序路径和指纹 | 总检、启动器、一键更新 |
| `应用直连防护状态.json` | 当前状态：Desktop 版本、8 条规则 | 总检、启动器、一键更新 |
| `应用直连防护-Verify.json` | 最近一次管理员核验结果，超过 30 天提示重做 | 总检、启动器 |
| `应用直连防护-最近操作.json` | 最近一次安装或移除防护规则的结果 | 总检、启动器 |
| `安装状态.json` | 43867 专用通道的安装状态 | `专用通道管理.ps1`，用来防止重复安装 |
| `应用直连防护-Refresh.json` | 仅记录：最近一次刷新指纹的报告，每次刷新重写 | 无 |
| `应用直连过滤.cs`、`独立网络探针.cjs` | 程序组件：防护规则代码、阻断测试探针 | `应用直连防护管理.ps1` |

## 官方包审核

- **来源**：固定来源和地址格式见 [claude-maintenance 固定来源](../../../../.agents/skills/claude-maintenance/SKILL.md#固定来源不要重新搜索)，由 `下载ClaudeDesktop官方包.ps1` 执行；不要去 `claude.com/download` 网页上找链接。
- **审核项**：Anthropic 有效签名、包家族、版本、依赖、Manifest 启动与服务声明；包架构必须与已装版本一致；新增可执行文件必须审阅保护范围。
- **安装源**：下载件先放在 `%LOCALAPPDATA%\ClaudeNetworkGuard\Desktop安装包下载\`，`一键更新` 再复制到 `%ProgramData%\ClaudeNetworkGuard\Claude-<版本>.msix` 并复核 SHA-256。
- **安装卷**：Stage 必须显式指定当前安装卷（09-20 未指定卷时报 `0x80070003`）。
- **禁止**：放宽系统权限或修改应用仓库来绕过错误。

## 执行顺序

1. 读实际版本、进程、HKLM 禁更与代理策略；确认旧版规则与指纹通过。
2. 备份将改动的清单、状态、策略、脚本。
3. Stage 新版文件 → 为新版主程序路径加规则并验证 → Register 切换版本。
4. 更新目标清单与状态，管理员 Verify；成功后只清理旧 Desktop 规则，保留 Code 规则。

依据：[微软对 Add、Stage、Register 的说明](https://devblogs.microsoft.com/insidemsix/add-vs-stage-and-register/)。

## 失败与同版本

| 情况 | 处理 |
|---|---|
| Register 前失败 | 修复原因后用原 `-ResumeJournal '<更新过程.json>'` 续接，避免再次 Apply 产生孤立规则 |
| Register 前文件占用 | 退出 Claude 后用 `ForceTargetApplicationShutdown` 清理目标包占用 |
| Register 后失败 | 保持应用关闭，按新版补齐防护、状态、同步与 Verify；不得恢复旧清单冒充已保护 |
| 版本相同 | 只核验并补齐收尾，不重复安装 |
| 想降级 | 配置备份不含旧安装包，不能承诺降级；不得直接跑整体 Rollback |

- **不采用 IFEO 启动锁**：试验中挡得住同名探针，挡不住真实 MSIX 启动，已移除。

## 同步与核验

- **活动源**：桌面快捷方式指向本目录；改 Skill 副本不能代替改这里。
- **Skill 副本**：一键更新自动把 4 个状态 json、`更新ClaudeDesktop.ps1`、`一键更新ClaudeDesktop.ps1` 复制到 `.agents/skills/claude-safe-network/scripts/desktop/维护文件/` 并比对 SHA-256；其他脚本两边路径不同，不要互相覆盖。
- **策略**：`disableAutoUpdates` 与 `egressProxyUrl=http://127.0.0.1:43867` 必须同在 HKLM 层；不得调用 `Claude自动更新管理.ps1 -Action Enable`（会删掉同层代理策略）。
- **收尾**：一键总检 + 启动器 `-CheckOnly`；结果按 claude-maintenance 追加到维护日志。

## 防护边界

- **匹配方式**：WFP 按完整程序路径阻断非回环出站，本机代理连接放行；SHA-256 只用来发现程序变化。
- **覆盖**：Desktop 主程序 + 两个 CLI npm 程序 + VS Code `anthropic.claude-code` 插件内置程序，共 4 个文件；不保护整个 `Code.exe`，Cowork、虚拟机、SSH 辅助程序、外部浏览器不在内。
- **同路径变化**（如 npm 更新）：审核来源、签名、指纹后，通过 `一键更新 -Action Update -CliApprovedSHA256 <按清单顺序的四个本次审核指纹>` 执行（内部就是 `Refresh -SkipNetworkProbe`）；指纹不能复制历史值。
- **插件路径**：从 `%USERPROFILE%\.vscode\extensions\extensions.json` 读取当前活动 `anthropic.claude-code`，要求唯一、`pinned=true`、`targetPlatform=win32-x64`，且没有 `claudeCode.claudeProcessWrapper`；任一项变化，总检和启动器都阻断通过。
- **路径变化**：Desktop 或插件升级换目录时必须迁移规则，不能只刷新指纹。插件由 `应用直连防护管理.ps1 -Action MigratePlugin` 完成（经一键更新调用）：先退出 VS Code 和全部 `claude.exe`，给新路径加规则并核验、更新清单和状态，最后撤旧规则；任一步失败就撤新规则、恢复清单，旧规则不动。
- **启动器**：只做启动前检查，不持续监视已运行程序。
- **跨机器**：新机器重新识别路径和目标，不能导入本机状态 JSON 充当验收。
