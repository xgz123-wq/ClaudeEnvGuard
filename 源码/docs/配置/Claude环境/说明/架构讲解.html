Claude Code · Claude Desktop · Clash Verge · Windows

把 Claude 的网络环境
配成一个正常人在上网

Claude 有三种用法：命令行的 Claude Code、网页版、Claude Desktop。它们运行时不只访问 claude.ai，还会请求 CDN、登录认证等一串域名。任何一个漏掉没走代理，就等于同一个账号的请求从两个国家发出——这是风控最敏感的信号。这份指南讲清三条路怎么汇到同一个出口，以及每个口子怎么堵上。

2026-09-23 版 · 按本套现行配置编写

这份是讲解，部署交给 AI

看完这份，你脑子里应该有一张图：每条流量走哪、每个设置管什么、出问题该去哪改。具体安装由 AI 按 AGENTS.md 一步步做：把整个文件夹当项目打开（Claude Desktop 的 Code 标签页或 Codex），说「按 AGENTS.md 帮我部署」。

壹这套解决什么问题

核心只有四条，其余都是为它们服务的：

目标怎么实现
Claude 只从一个固定出口出去Clash 自建 ACCOUNT-US 组，Claude 规则排最前面；三个入口最后都汇到这个组
没有请求能绕过代理Clash TUN 接管全机；Windows 防火墙（WFP）规则禁止 Claude 程序直接连外网
堵住 DNS、IPv6、WebRTCClaude 域名走加密 DNS；IPv6 三层关闭；专用浏览器堵 WebRTC
国内应用不受影响只动 Claude 相关的规则和 DNS，普通流量仍按订阅规则分流

一张图看懂：三个入口，一个出口

入口在哪设置端口怎么进 ACCOUNT-US
Claude Code~/.claude/settings.json 的 envHTTP 43865按规则：Claude 域名规则置顶，命中后进组
专用 Chrome桌面快捷方式的启动参数SOCKS 43866入站规则 IN-NAME：从这个口进来的全部进组
Claude Desktop注册表 HKLM 策略 egressProxyUrlHTTP 43867监听器直接写 proxy: ACCOUNT-US，不经过规则
其他应用不设置TUN 接管按订阅规则走；访问 Claude 域名也会命中置顶规则
为什么 Chrome 和 Desktop 整口进组，Code 却按规则？

Chrome 和 Desktop 的专用口只给 Claude 用，整口进组最省心、也不会漏；Code 用的是 Clash 公共的混合端口，它还要访问 npm、GitHub 等别的站点，所以按域名分流。

先确认一件事：Claude Code 连的是不是 Anthropic 官方

如果 settings.json 里有 ANTHROPIC_BASE_URL 指向第三方网关，Claude Code 的请求发去的是网关，Claude 域名规则对它不生效，出口也不是你以为的那个。指向你自己本机的转发程序则另当别论，按那个程序自己的出口判断。

贰一条重要原则

这份指南里的东西分两类。搞混了会让你的配置静默失效——看起来一切正常，实际根本没按规则走。

本套约定 · 直接用
  • 三个端口 43865 / 43866 / 43867
  • 专用组名 ACCOUNT-US
  • Claude 的域名清单（在全局脚本里）
  • Clash 的开关在哪一页
  • Chrome 启动参数
因人而异 · 查你自己的
  • 订阅、选哪个节点
  • 你的出口 IP
  • Claude Desktop / Code 的安装路径和程序指纹
  • 账号别名、浏览器数据目录
最容易翻车的地方

一条规则如果指向一个你机器上不存在的代理组，Clash 不会报错，只会静默跳过，最后掉到兜底规则。表面一切正常，实际这条规则从没生效过。

所以本套的全局脚本自己建组，不引用任何订阅自带的组名；三个端口也写死在全套脚本和检查里，不建议改。

叁第一步 · 先测，别急着配

配之前先存一份基线，配完才知道哪里变好了。打开这四个页面各截一张图：

  1. ip.net.coffee/claude — 出口 IP、信任评分、是不是住宅 IP
  2. ip.net.coffee/dns — DNS 有没有泄漏到国内运营商
  3. ip.net.coffee/webrtc — 有没有暴露你的真实 IP
  4. ip.net.coffee 首页分流测试 — claude.ai 和 anthropic.com 是不是同一个出口
出口 IP 好不好，看三个字段

页面上 hosting、proxy、mobile 三项都必须是 false，而且这个 IP 归属的公司要是真实的宽带运营商，不是卖代理的公司。

只看前三项不够——卖代理的 IP 也能显示 false，一定要再看归属公司。

肆第二步 · Clash Verge

Clash 是整套的地基：三个入口都进它，规则、专用组、专用端口、Claude 的 DNS 都在这里。

2.1 这几项只能在设置页改

写进配置文件是无效功

Clash Verge 有个保护机制，下面这些键只认设置页里的值。你写进 Merge 或脚本里会被覆盖回去，配置里没有的键甚至会被删掉。

mode · tun · mixed-port · allow-lan · log-level · ipv6 · unified-delay · external-controller · secret

  1. 左侧「设置」→ 模式选 规则
  2. 打开虚拟网卡模式（TUN）
  3. 关闭系统代理（TUN 已经接管，两个都开容易互相打架）
  4. 关闭 IPv6
  5. 打开 DNS 覆写，进去把里面的 IPv6 也关掉
  6. 「端口设置」里的混合端口设为 43865，Claude Code 要用

2.2 全局扩展脚本

这是整套配置的核心，文件在 docs/配置/Claude环境/Clash/Clash全局账号通道.js。它不需要改任何地方，端口和组名都是本套约定值。

  1. Clash Verge → 左侧「订阅」
  2. 右上角「全局扩展脚本」
  3. 把下面的内容全部粘贴进去，保存（AI 部署时由安装脚本写入，效果相同）
Clash全局账号通道.js · 全局扩展脚本（讲解节选）
function main(config, profileName) {
  var groupName = "ACCOUNT-US";
  var listenerName = "account-us-socks";
  var inboundRule = "IN-NAME," + listenerName + "," + groupName;
  var accountDnsServers = [
    "https://1.1.1.1/dns-query#" + groupName,
    "https://8.8.8.8/dns-query#" + groupName
  ];
  var accountDnsDomains = [
    "+.anthropic.com",
    "+.claude.ai",
    "+.claude.com",
    "+.claude.app",
    "+.clau.de",
    "+.claudemcpclient.com",
    "+.claudemcpcontent.com",
    "+.claudeusercontent.com"
  ];
  var legacyAccountDnsDomains = [
    "+.sentry.io",
    "+.statsigapi.net",
    "+.datadoghq.com",
    "+.intercom.io",
    "+.intercomcdn.com"
  ];
  var claudeRuleMatchers = [
    "DOMAIN-SUFFIX,anthropic.com",
    "DOMAIN-SUFFIX,claude.ai",
    "DOMAIN-SUFFIX,claude.com",
    "DOMAIN-SUFFIX,claude.app",
    "DOMAIN-SUFFIX,clau.de",
    "DOMAIN-SUFFIX,claudemcpclient.com",
    "DOMAIN-SUFFIX,claudemcpcontent.com",
    "DOMAIN-SUFFIX,claudeusercontent.com",
    "DOMAIN,servd-anthropic-website.b-cdn.net",
    "DOMAIN,anthropic.com.cdn.cloudflare.net",
    "DOMAIN,anthropic.auth0.com",
    "DOMAIN,anthropic-com.ghost.io"
  ];
  var claudeRules = claudeRuleMatchers.map(function (matcher) {
    return matcher + "," + groupName;
  }).concat([
    "IP-CIDR,160.79.104.0/21," + groupName + ",no-resolve",
    "IP-CIDR6,2607:6bc0::/32," + groupName + ",no-resolve",
    "IP-ASN,399358," + groupName + ",no-resolve"
  ]);
  var legacyMatchers = claudeRuleMatchers.concat([
    "DOMAIN,claude.com",
    "DOMAIN,clau.de",
    "DOMAIN,claudemcpclient.com",
    "DOMAIN,claudemcpcontent.com",
    "DOMAIN,claudeusercontent.com",
    "DOMAIN,sentry.io",
    "DOMAIN,statsigapi.net",
    "DOMAIN,cdn.anthropic.com",
    "DOMAIN,mcp.anthropic.com",
    "DOMAIN,console.anthropic.com",
    "DOMAIN,workbench.anthropic.com"
  ]).concat([
    "DOMAIN-SUFFIX,sentry.io",
    "DOMAIN-SUFFIX,statsigapi.net",
    "DOMAIN,browser-intake-us5-datadoghq.com",
    "DOMAIN-KEYWORD,datadog",
    "DOMAIN-KEYWORD,sift",
    "DOMAIN-SUFFIX,intercom.io",
    "DOMAIN-SUFFIX,intercomcdn.com",
    "DOMAIN,cdn.usefathom.com"
  ]);

  function isManagedClaudeRule(rule) {
    if (typeof rule !== "string") {
      return false;
    }
    if (rule === inboundRule) {
      return true;
    }
    if (rule.indexOf("IP-CIDR,160.79.104.0/21,") === 0 ||
        rule.indexOf("IP-CIDR6,2607:6bc0::/32,") === 0 ||
        rule.indexOf("IP-ASN,399358,") === 0) {
      return true;
    }
    return legacyMatchers.some(function (matcher) {
      return rule.indexOf(matcher + ",") === 0;
    });
  }

  if (!Array.isArray(config["proxy-groups"])) {
    config["proxy-groups"] = [];
  }
  config["proxy-groups"] = config["proxy-groups"].filter(function (group) {
    return !group || group.name !== groupName;
  });
  config["proxy-groups"].unshift({
    name: groupName,
    type: "select",
    "include-all-proxies": true,
    "exclude-type": "Direct|Reject"
  });

  // 只加固 Claude 链路：相关域名使用加密 DNS，且 DoH 连接明确经过 ACCOUNT-US。
  // 普通/国内 DNS 保留订阅与 Clash 的通用解析器，不绑定任何专用代理组。
  if (!config.dns || typeof config.dns !== "object") {
    config.dns = {};
  }
  if (!config.dns["nameserver-policy"] ||
      typeof config.dns["nameserver-policy"] !== "object" ||
      Array.isArray(config.dns["nameserver-policy"])) {
    config.dns["nameserver-policy"] = {};
  }
  legacyAccountDnsDomains.forEach(function (domain) {
    delete config.dns["nameserver-policy"][domain];
  });
  accountDnsDomains.forEach(function (domain) {
    config.dns["nameserver-policy"][domain] = accountDnsServers.slice();
  });

  // 2026-09-11 DNS 分层：不覆盖 nameserver、direct-nameserver 或 fallback。
  // 这样飞书等普通应用的 DNS 不依赖 ACCOUNT-US；Claude 域名仍由上方 policy 加固。
  config.dns.enable = true;

  // Windows 多网卡 DNS 旁路防护：ETW 已确认 WLAN 与 TUN 并行代查。
  config.tun = config.tun || {};
  config.tun["strict-route"] = true;
  config.tun["dns-hijack"] = ["any:53", "tcp://any:53"];

  if (!Array.isArray(config.listeners)) {
    config.listeners = [];
  }
  config.listeners = config.listeners.filter(function (listener) {
    return !listener || listener.name !== listenerName;
  });
  config.listeners.unshift({
    name: listenerName,
    type: "socks",
    listen: "127.0.0.1",
    port: 43866,
    udp: false
  });

  // Claude Desktop：HTTP 专用入口直接进入账号组，不改变其他应用的 DNS/分流。
  config.listeners = config.listeners.filter(function (listener) {
    return !listener || listener.name !== "claude-desktop-http";
  });
  config.listeners.unshift({
    name: "claude-desktop-http",
    type: "http",
    listen: "127.0.0.1",
    port: 43867,
    proxy: groupName,
    users: []
  });

  if (!Array.isArray(config.rules)) {
    config.rules = [];
  }
  config.rules = config.rules.filter(function (rule) {
    return !isManagedClaudeRule(rule);
  });
  config.rules = [inboundRule].concat(claudeRules, config.rules);

  // 使用 Mihomo 官方生态 MetaCubeX 数据，每日更新；失败时继续保留本地旧文件。
  config["geo-auto-update"] = true;
  config["geo-update-interval"] = 24;
  if (!config["geox-url"]) {
    config["geox-url"] = {};
  }
  config["geox-url"].geoip = "https://github.com/MetaCubeX/meta-rules-dat/releases/download/latest/geoip.dat";
  config["geox-url"].geosite = "https://github.com/MetaCubeX/meta-rules-dat/releases/download/latest/geosite.dat";
  config["geox-url"].mmdb = "https://github.com/MetaCubeX/meta-rules-dat/releases/download/latest/country.mmdb";
  config["geox-url"].asn = "https://github.com/MetaCubeX/meta-rules-dat/releases/download/latest/GeoLite2-ASN.mmdb";

  return config;
}
这是讲解用节选，别直接拿去用

上面这段用来讲清逻辑，和仓库里真正的 Clash/Clash全局账号通道.js 并不逐字相同（节选里没有 DoH 端点强制直连、邮件端口规则清理、geox-url 国内镜像等几处）。实际部署以文件或安装脚本写入的版本为准，手工粘贴请打开 Clash/Clash全局账号通道.js 整份复制。

脚本做了什么为什么
新建 ACCOUNT-US 组（包含订阅全部节点，由你手选一个）不依赖订阅的组名，换订阅后组还在，重选一次节点即可
规则最前面插入：入站 IN-NAME + 12 条 Claude 域名 + 3 条 IP 兜底（160.79.104.0/21、2607:6bc0::/32、AS399358）Claude 流量不会被订阅里的其他规则截走
建两个监听：SOCKS 43866（给 Chrome）、HTTP 43867（给 Desktop，直接指向组）浏览器和桌面版有专属入口，整口进组
Claude 的 8 个域名后缀用 DoH（1.1.1.1 / 8.8.8.8）解析，DoH 连接本身也走专用组Claude 域名的解析不经过国内运营商
TUN 开 strict-route，dns-hijack 接管所有 53 端口Windows 多网卡会并行查 DNS，不接管就有绕行
清掉旧规则，包括以前让 sentry、statsig、datadog、intercom 等第三方监控也走专用组的写法这些第三方服务别的软件也在用，塞进专用组会把出口用杂；现在交给订阅规则
geo 数据库（含 ASN 库）改用 MetaCubeX 源，每天更新IP-ASN 规则缺库会让整份配置加载失败

而规则覆写的 prepend 在第 ② 层，会被后面的层覆盖。

2.4 选节点 —— 这一步最关键

保存脚本后到「代理」页，会看到多了一个 ACCOUNT-US 组。

务必让 Claude 独占一个节点

规则链的最后一条通常是 MATCH 兜底，它把全机所有其他流量都送给某个组。如果那个组和 ACCOUNT-US 选了同一个节点，那么 YouTube、GitHub、Netflix 加上所有兜底流量，全都和 Claude 从同一个 IP 出去。

这会把你精心挑的干净 IP 用脏。给两个组选不同的节点。

  1. ACCOUNT-US 组 → 选一个你要长期用的节点，之后不要乱换
  2. 订阅自带的主组（MATCH 指向的那个）→ 选另一个不同的节点

2.5 改完必须重新加载并核验

本方案不依赖 mihomo 的 9097 HTTP 控制端口；项目脚本可以通过 \\.\pipe\verge-mihomo 命名管道执行受控热重载。手动改配置后由用户在 Clash Verge 中应用或重载，再运行验证脚本读取运行态；模型默认不代用户重启或热重载 Clash。

2.6 关于通用国外服务的规则

一个简单的判断法

很多人会加一堆 DOMAIN-SUFFIX,openai.com,某组。看这条规则的目标组，和最后那条 MATCH 兜底的目标组是不是同一个——是的话命中与否结果完全一样，纯属重复，还硬编码了订阅组名。

只保留 Claude 那一套。其他国外服务交给订阅原生分流 + MATCH 兜底就够了。

伍第三步 · DNS 与 IPv6

代理只管「连接」，DNS 查询和 IPv6 是另外两条可能漏出去的路。原则：只加固 Claude 相关的部分，普通 DNS 不动，免得把飞书、企业内网这类国内应用搞断。

IPv6 为什么要关三层

  • 网卡那层按网卡生效，换 Wi-Fi 不用重做；插了新网卡（USB 网卡等）要重新取消勾选。命令等价操作（管理员）：Disable-NetAdapterBinding -Name 'WLAN' -ComponentID ms_tcpip6
  • 虚拟网卡不用管：Mihomo（TUN）、蓝牙、WSL 等虚拟网卡的 IPv6 勾由驱动管，取消了也会自己恢复；它们没有公网 IPv6 地址，形不成泄漏。验收看检测页有没有公网 IPv6
  • 自动检查：五项自检会检查物理网卡的 IPv6 绑定

陆第四步 · Claude Code 的代理

位置 Windows 是 C:\Users\你的用户名\.claude\settings.json，Mac / Linux 是 ~/.claude/settings.json。只把下面的键合并进 env 里，不要整份覆盖原文件——里面可能还有你别的配置。

settings.json
{
  "env": {
    "HTTP_PROXY": "http://127.0.0.1:43865",
    "HTTPS_PROXY": "http://127.0.0.1:43865",
    "ALL_PROXY": "http://127.0.0.1:43865",
    "NO_PROXY": "localhost,127.0.0.1,*.local",
    "DISABLE_AUTOUPDATER": "1"
  }
}
为什么这么填
三个 PROXY 都要填Claude Code 不同请求读不同变量，只填一个会有请求漏出去不走代理
HTTPS_PROXY 也写 http://没写错。它表示"通过 HTTP 代理转发 HTTPS 请求"
NO_PROXY 的坑底层是 Node，只认主机名不认网段。写成 127.0.0.0/8 永远不生效，必须写 127.0.0.1
关自动更新更新中途断掉会把 claude 命令弄坏；而且程序文件一变，直连防护的指纹要重新登记，所以改成手动更新
可选："BROWSER": "C:\\Users\\你的用户名\\noop-browser.bat"指向一个只有 @echo off 的空脚本，claude /login 就不会自动拉起默认浏览器（普通 Chrome）；授权链接改为手动复制进专用 Chrome 打开。本套默认不配，想让登录只发生在专用浏览器里再加
不要把 SOCKS 端口填在这里

Claude Code 不支持 SOCKS 代理。给专用浏览器用的 43866 绝对不能填进 settings.json。

怎么验收（有个陷阱）

运行 /status 看到 Proxy 有值，只能证明代理变量被读到了，不能证明流量真的走了你想要的出口。

真正的验收看 Clash「连接」页里 api.anthropic.com 是否命中 ACCOUNT-US，见验收一节。

柒第五步 · 专用浏览器

不要用 Chrome 的「添加用户」按钮

那个按钮只是在同一个数据目录下多开一个 Profile，cookie 仍然互通。同一个目录登过两个号，后台会直接把两个号认成同一个人。

正确做法是用启动参数指定完全独立的数据目录。本套用 创建账号浏览器.ps1 -Alias 别名 自动生成快捷方式，每个账号一个。

Chrome 启动参数（脚本生成的内容）
--user-data-dir="%LOCALAPPDATA%\ClaudeBrowsers\账号别名\UserData" --proxy-server="socks5://127.0.0.1:43866" --host-resolver-rules="MAP * ~NOTFOUND, EXCLUDE 127.0.0.1, EXCLUDE localhost" --lang=en-US --accept-lang="en-US,en" --force-webrtc-ip-handling-policy=disable_non_proxied_udp
参数作用
--user-data-dir给这个账号一个完全独立的数据目录。每个账号换一个别名，不能共用
--proxy-server整个浏览器走专用口 43866。用 SOCKS5，也别用 --proxy-pac-url，那会让一部分网址走本地 DNS
--host-resolver-rules浏览器自己完全不查 DNS，全部交给代理那头解析。副作用：顶部会提示「不受支持的命令行标记」，可忽略
--lang / --accept-lang浏览器界面和网页语言用英文（Mac 上 --lang 无效，只用 --accept-lang）
--force-webrtc-ip-handling-policy堵 WebRTC。它会绕过代理用 UDP 直接暴露真实 IP，是最常见的漏 IP 口子

怎么确认配对了

从这个快捷方式打开浏览器，地址栏输入 chrome://version，看「命令行」那行是不是同时包含独立目录和 43866。

想看快捷方式里的完整参数：右键 → 属性 → 点进「目标」栏按 Ctrl+A 再复制。直接拖选常常只拷到可见部分，看起来像参数丢了。

入口纪律是防线的另一半

这些参数只在桌面专用快捷方式里。从开始菜单、任务栏或普通 Chrome 图标打开的浏览器一个参数都没有，等于没防护。专用浏览器只从桌面快捷方式进。

Desktop 不读 settings.json 的代理，也没有启动参数可加。本套用它官方支持的企业策略指定代理，再用 Windows 防火墙兜底。

自动更新不要用 Enable 打开

Claude自动更新管理.ps1 -Action Enable 会连带删掉同一位置的代理策略，Desktop 就不走 43867 了。更新一律交给 AI 按 claude-maintenance 流程做。

为什么要登记程序指纹

防护规则按程序路径匹配，指纹（SHA-256）用来确认这个路径下还是审核过的那个程序。软件更新后指纹会变，总检报「指纹 1/3」之类的 FAIL，启动器也会拒绝启动——这是保护，不是坏了。对 AI 说「我已手动更新，请同步」即可。

三个"出口"不是一回事

拾肆哪些流行说法靠不住

网上的配置教程互相矛盾的地方不少。这几条是核对过的：

流行说法实际情况
"要加 NTP 分流规则，因为 Claude 通过 NTP 判断你的时区"站不住。NTP 协议只传 UTC 时间戳，协议里根本没有时区字段；网页读的是系统时区
"配置里加一行 ipv6 = false 就行"这个等号写法不属于任何主流代理内核。Clash 是 ipv6: false（冒号），而且要在设置页改
"把 network 设成 tcp 来禁用 UDP"那是 Xray 的写法。在 Clash 里 network 是节点传输层（ws/grpc/h2），跟禁不禁 UDP 毫无关系
"遥测、监控域名也要塞进 Claude 专用组"sentry、datadog 等是第三方服务，别的软件也在用，塞进去只会把出口用杂。本套已移除
"家宽 IP 变了会触发风控"两种说法都有。较可信的是：家宽可以变，机房不能变——IP 的行为模式要符合它的类型
