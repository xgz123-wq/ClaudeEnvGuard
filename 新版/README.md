# Claude 环境卫士 v2

按**出口 IP** 检查并修复 Claude 三个入口（专用浏览器、Claude Code、Claude Desktop）的使用环境。配合「Claude 环境分享包」使用：分享包负责搭环境，本工具负责体检、一键修复和还原。

- **定位（2026-10-11 用户确认）**：自用的日常体检。换节点 / IP 之后双击看一眼；Claude 或 Clash 更新之后，再点「深度总检」（v2.4.0 起，就是 `docs/配置/Claude环境/Claude环境一键总检.ps1`；Clash 规则、脚本哈希、直连防护的管理员实时校验只有总检有）。修复、还原、清理保留原样。

## 怎么用

| 场景 | 做法 |
|---|---|
| 日常体检 | 双击桌面「Claude 环境卫士」，打开即自动检查，约 5 秒出完整结果 |
| 有没配好的项 | 点结论区的「一键修复」，计划直接在下方明细区展开，看清每一处改动后勾选执行；需要管理员的项只弹一次 UAC；修完 10 秒内可点「撤销这次修复」 |
| 修错了 / 想撤销 | 顶栏「记录」页：选一次修复，只勾想撤回的项，点「还原勾选的 N 项」，没勾的保持现状 |
| 更新 Claude 三端 | 切到「更新」页：打开卫士、体检完成后自动查一次版本；有更新时先退出全部 Claude，再点「一键更新」（要动防护时弹一次 UAC，那就是确认）。和桌面「Claude-三端更新」调同一个脚本、记录放同一个目录，见下面「更新页」 |
| 换账号 / 重新登录 | 选「专用浏览器 / Claude Code / Claude Desktop」卡片，点明细区上方的「清理登录…」，先列清单、勾「我核对过」才删；删了什么记进「记录」页 |
| Claude / Clash 更新后深查 | 「系统」卡片或 ⋯ 菜单的「深度总检」：约 15 秒，逐项列 PASS / WARN / FAIL / MANUAL，和桌面「Claude-环境一键总检」同一个脚本，只读 |
| 英文界面启动 Desktop | 「Claude Desktop」卡片的「检查后启动 Desktop（英文）」：先跑英文启动器的启动前检查，全部通过才按桌面「Claude-英文浏览器」原样启动；弹出的黑色窗口守着 Claude，**关掉它 = 退出 Claude** |
| 改端口、目标地区、起始网址 | 顶栏「⚙ 设置」：保存后自动重新检查；「数据放在哪」每个位置都能直接打开 |
| 命令行或给 AI 用 | `ceg check`、`ceg fix --plan`，见下表 |

- **首次运行**：exe 没有代码签名，Windows SmartScreen 可能提示「已保护你的电脑」，点「更多信息 → 仍要运行」。
- **依赖**：图形界面需要 WebView2 运行库（Windows 11 自带）；命令行版 `ceg.exe` 不依赖它。

## 命令行（ceg.exe）

| 命令 | 作用 |
|---|---|
| `ceg check [--browser 名字] [--offline] [--json] [--verbose]` | 全量检查；`--offline` 跳过联网项 |
| `ceg fix --plan [--json] [--alias 名字]` | 只列修复计划，不改任何东西 |
| `ceg fix --apply --items default` | 执行计划里默认勾选的修复（先备份） |
| `ceg fix --apply --items sys.timezone,cli.proxy` | 执行指定修复 |
| `ceg restore [--list] [--id 备份编号]` | 还原某次修复，不带 `--id` 还原最近一次；`--list` 列出每次修复里的每一项（动作 id）和还原状态 |
| `ceg restore --id 备份编号 --items sys.timezone` | 按项还原：只还原列出的动作，其余保持现状 |
| `ceg records [--json]` | 只读：列出「记录」页的修复、还原、更新、清理 |
| `ceg clean code\|desktop\|browser --plan` / `--yes` | 清理登录数据：先看清单，再确认执行 |
| `ceg update --check [--json] [--script]` | 只读：查三端版本、4 个程序指纹和这次会做什么；默认 Go 直接查（约 2 秒），`--script` 改调脚本 `-Action Check`，对照用 |
| `ceg update --apply` | 一键更新（同桌面「Claude-三端更新」）；先退出全部 Claude |
| `ceg deep [--json]` | 只读：深度总检（同桌面「Claude-环境一键总检」），约 15 秒；退出码 0 没有失败，2 有失败或没跑成 |

- **退出码**：0 全部通过；1 有警告或未知；2 有失败；3 工具自身出错。`update`：0 已是最新或更新完成；1 有可更新的或要先处理；2 失败或安全检查没过。
- **JSON**：`--json` 输出与图形界面同一份数据结构（`internal/model`）。

## 检查项

「类型」：**固定** = 和地区无关，谁都该这样；**随 IP** = 目标值按出口所在地推算，换节点会跟着变；**信息** = 只做参考。带「可选」的不计入结论，只在「可选优化」里提示。

| ID | 卡片 | 检查 | 类型 | 一键修复 |
|---|---|---|---|---|
| P1 | 线路 | 三个专用端口（默认 43865/43866/43867）由代理客户端监听 | 固定 | 否（装 Clash 属分享包） |
| P2 | 线路 | Clash Verge：TUN 开、系统代理关、混合端口一致、两个专用监听器存在 | 固定 | 否 |
| P3 | 线路 | 三个入口从同一个出口 IP 出去 | 固定 | 否 |
| P4 | 线路 | 出口不在 Claude 不支持的地区 | 固定 | 否 |
| P5 | 线路 | 出口 IP 质量（ip.net.coffee 信任评分、是否住宅） | 信息 | 否 |
| B1 | 专用浏览器 | 有独立数据目录 + 桌面快捷方式 | 固定 | 新建 / 补快捷方式 |
| B2 | 专用浏览器 | 快捷方式启动的是 Chrome | 固定 | 是 |

| B6 | 专用浏览器 | 浏览器语言与出口地区一致（英语任何地区都接受） | 随 IP | 是 |
| B7 | 专用浏览器 | 正在运行的窗口带着防护参数（防止绕开快捷方式打开） | 固定 | 否（关掉重开） |
| B8 | 专用浏览器 | 经浏览器端口能到 claude.ai | 固定 | 否 |
| C1–C6 | Claude Code | 安装、settings.json 代理、无第三方接口变量、全局代理变量、自动更新（装了防护时）、API 可达 | 固定 | C2–C5 可修 |
| D1–D4 | Desktop | 安装、HKLM 代理策略（含同层 disableAutoUpdates）、直连防护证据、可达 | 固定 | D2 可修（需管理员） |

| S2 | 系统 | 区域格式与「国家或地区」（可选） | 随 IP | 是，默认不勾 |
| S3 | 系统 | Windows 显示语言（可选） | 随 IP | 否，给手动步骤 |
| S4 | 系统 | **IPv6 防漏**：不经代理请求纯 IPv6 地址，看能否绕出去 | 固定 | IPv4 优先（需管理员、重启） |
| S5 | 系统 | 不走专用端口的程序用的 DNS（可选、仅参考） | 信息 | 否 |
| S6 | 系统 | Windows 系统代理（可选） | 信息 | 否 |
| S7 | 系统 | Anthropic 网段 `160.79.104.0/23` 直连阻断（可选） | 固定 | 是，默认不勾 |

## 「随 IP」怎么定目标

1. 三个入口各自经自己的端口请求 `claude.ai/cdn-cgi/trace`，拿到 Claude 实际看到的 IP 和国家。
2. 用 ip.net.coffee 的 `iprisk` 接口查城市、IANA 时区、信任评分；失败时退到 ipinfo.io；再失败就只用国家和该国默认时区。
3. 时区按 CLDR `windowsZones` 换成 Windows 时区 ID（内置在程序里）；语言按国家常用语言，查不到用 `en-US`。
4. 优先用浏览器入口的出口；用户在「设置」里手选地区时以手选为准。

## 状态与兜底

- **五种状态**：通过、警告、失败、未知、不适用。读不到、超时、出错一律「未知」，**绝不显示通过**；联网项没回来之前显示「检测中」。
- **隔离**：本地每个收集器独立超时（1.5–2.5 秒）、独立捕获异常；联网阶段总预算 14 秒，单个请求 6 秒。
- **网络探测**：每个请求都显式指定走哪个端口，忽略进程环境里的 `HTTPS_PROXY`；Claude 域名只经专用端口访问。
- **修复**：每个动作要么全部完成，要么自动撤回；每步执行前把旧值或旧文件存进备份；`settings.json` 格式损坏时拒绝改写。
- **提权**：需要管理员的动作交给同一个 exe 的提权子进程执行，请求文件只接受本工具备份目录，且每一步都要通过白名单校验（只允许改 Claude 策略、时区、IPv6、指定环境变量、指定防火墙规则）。
- **清理**：只删白名单内的登录和缓存数据；目标程序在运行时拒绝；执行前重新确认进程状态；登录凭据不留备份。每次清理写一份留痕（删了哪些路径、`.claude.json` 删了哪些字段名），不含凭据内容。
- **按项还原**：每次修复的 `manifest.json` 记下每个动作的标题和改动（v2.2.0 起），每条改动记还原时间；只还原选中的动作，需要管理员的部分照样只弹一次 UAC，提权进程只动选中的项。v2.2.0 之前的备份按备份记录现场拼出逐项清单，同样能还原。

## 更新页（v2.1.0 起）

- **只套界面**：更新仍由 `AI应用开发\docs\配置\Claude环境\Desktop防护\更新三端Claude.ps1` 执行（找不到时依次找设置里的分享包目录、`桌面\Claude环境分享版`）；卫士只调用它、读它写的记录文件，不下载、不安装、不改防护。
- **查版本用 Go（v2.3.0 起）**：`internal/update/gocheck.go` 做和脚本 `-Action Check` 同样的事——Desktop 官方跳转入口、`registry.npmjs.org`、VS Code 官方市场三个源同时查，只经 Desktop 专用端口；本机版本读 MSIX 包全名、`package.json`、`extensions.json`；4 个程序的指纹同时算，对不上才用 WinVerifyTrust 校验 Anthropic 签名；结果写成同样的 `检查记录.json`。本机约 2 秒（脚本约 3 秒，另加启动 PowerShell）。来源、判定规则、出错原文都照脚本同名函数，**改脚本的查版本逻辑时这里要跟着改**；`ceg update --check --script` 可随时对照。
- **调用方式**：一键更新在隐藏窗口跑 `-RunDirectory <更新记录-时间> -ChangedOnly`（UAC 内的日常总检只查这次动过的项）；脚本自己会再查一次版本。两个参数不传时脚本行为不变，桌面图标照常可用。
- **进度从哪来**：`记录.json` 的 `Timing`、`统一维护\进度.log`、下载中的临时文件大小；剩余时间按最近 5 次 `更新记录-*\记录.json` 每步耗时估（样本不足 3 个取最近一次）。
- **插件自动更新（v2.5.0 起）**：插件落后时脚本用 VS Code 命令行 `code --install-extension anthropic.claude-code@<最新版>` 装，归在第 2 步「下载与安装」；装完核对 `extensions.json` 只登记一条、`pinned=true`、`targetPlatform=win32-x64`，不合格就用装之前的备份恢复并报失败；随后在同一次 UAC 里迁移防护规则。VS Code 开着时「要先处理」只列「退出 VS Code」，不强杀。2026-10-24 实测：命令行指定版本装插件（2.1.310 → 2.1.309 → 2.1.310），两项都不变。脚本里没有 `--install-extension` 的旧脚本仍按原来「在 VS Code 点更新」处理。
- **出错分三层**：网络断、下载不完整、超时 → 「重试这一步」（连续失败 2 次升到第三层）；Claude 或 VS Code 在运行、UAC 点了否 → 列成待办；签名不对、防护核验不过、没见过的错 → 「复制给 AI 排查」。
- **关窗**：更新进行中关窗会先确认；脚本不跟着窗口停，关掉只是看不到进度。
- **回退**：见 [更新并入需求.md](../历史/更新并入需求.md) 第 2.1 节；删掉 `internal/update`、`frontend/src/update.*` 和顶栏「更新」页签，其余功能不受影响。

## 深度总检与英文启动器（v2.4.0 起）

- **只套界面**：`internal/envscripts` 调桌面两个图标背后的脚本，找脚本的顺序和更新页一样（`AI应用开发` → 设置里的分享包目录 → `桌面\Claude环境分享版`）。
- **深度总检**：跑 `Claude环境一键总检.ps1 -ResultPath <文件>`，读它写的 JSON（字段同 Skill 版 `-Json`）；不带 `-OpenBrowser`，不打开浏览器。脚本太旧、没有 `-ResultPath` 时提示先同步脚本。
- **英文启动器**：先跑 `启动Claude英文浏览器.ps1 -CheckOnly`，解析 `[PASS]` / `[BLOCK]` 行；有 `[BLOCK]` 就不启动并显示原因（例如 Claude Desktop 已在运行）。全部通过才按桌面快捷方式的目标和参数原样启动；没有快捷方式时用 `pwsh -NoProfile -File` 跑同一个脚本。
- **五项自检**：逐项对比见 [五项自检对比.md](../历史/五项自检对比.md)；桌面图标都没删。

## 界面结构（v2.2.0 起，照 [原型](../原型/环境卫士原型.html)）

| 位置 | 内容 |
|---|---|
| 顶栏 | 「体检 / 更新 / 记录」三个页签（带角标）；右边上次检查时间、⚙ 设置（单独一页）、⋯（离线检查、深度总检、复制报告、打开日志目录） |
| 体检页 | 结论区（一句结论 + 唯一主按钮 + 「随 IP 项按：… 改」）＋ 线路图（检查时连线流动，点它看 P1–P5）＋ 6 张卡片（需要处理 / 线路 / 专用浏览器 / Claude Code / Desktop / 系统）＋ 选中卡片的明细（有问题的排前面，通过的收成一行）；一键修复计划、清理登录清单都在明细区展开 |
| 记录页 | 左边按时间列出修复、还原、更新、清理（可筛），右边「改了什么：改之前 → 改之后」；修复记录逐项勾选还原；更新写明不能回退，清理写明不可恢复 |
| 设置页 | 三个端口、目标地区、默认专用浏览器与起始网址（默认 `https://ip.net.coffee/claude/`）、分享包目录、数据位置（各带「打开」）、版本与命令行用法 |

## 开发

| 要做什么 | 命令 |
|---|---|
| 测试 + 打包 | `pwsh -File 打包.ps1`（加 `-Deploy` 复制到上一级目录） |
| 只跑测试 | `go test ./...` |
| 真机只读测速 | `$env:CEG_REAL=1; go test ./internal/facts -run TestReal -v` |
| 界面预览（模拟数据） | `cd frontend; npm run dev`，地址加 `?s=real` / `?s=fresh` / `?s=split` 切换体检场景，`?r=empty` 看空的记录页，`?u=update` / `cli` / `blocked` / `latest` / `neterr` / `fail` / `checkfail` / `unsafe` / `never` 切换更新页场景（`dev/*.json` 由 `ceg check --json` 生成，不入库） |

- **开发规范**（分支、版本号、上线步骤）：见上级目录 [维护者指南.md](../维护者指南.md)。
- **结构**：`internal/facts` 收集现场（只读）→ `internal/checks` 纯函数判定 → `internal/fixes` 计划/执行/还原 → `internal/engine` 串起来；`internal/update` 是更新页（只调三端更新脚本、读它写的记录）；`internal/records` 汇总记录页（只读）；`internal/envscripts` 调深度总检和英文启动器脚本；`app.go` + `frontend/` 是界面（`check.ts`、`update.ts`、`records.ts`、`settings.ts` 各管一页，`ctx.ts` 是页间共享状态），`cmd/ceg` 是命令行。所有系统调用都在 `internal/platform` 的 `OS` 接口后面，测试用 `Fake`。
- **工具链**：Go 1.27（`%LOCALAPPDATA%\Programs\go`）、Wails v2.14、Node 24。不要用 conda 的 python，也不需要 Python。

## 已知限制

- **直连防护（D3）**：实时 WFP 规则需要管理员才能读，这里只核对分享包留下的证据文件和程序哈希。
- **网页实测**：WebRTC、浏览器 JS 时区等只能在浏览器里看；工具检查的是启动参数和系统设置，最终以专用浏览器打开 ip.net.coffee/claude 人工复核为准（专用浏览器卡片有「打开这个浏览器」按钮）。
- **其他代理客户端**：端口、出口、DNS 等通用项都能查；P2 只认 Clash Verge 的配置文件。
